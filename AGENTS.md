# Repository Guidelines

## Project Structure & Module Organization

- `src/main.rs`: entry point and CLI; `src/live.rs` and `src/live/`: production GTK workflows; `src/ui.rs` and `src/model.rs`: shared UI and demo behavior.
- `src/engine/`: backend adapters, source safety, jobs, SQLite sessions, consolidation and tests.
- `ui/`: embedded GtkBuilder XML, CSS and demo artwork. `packaging/` contains desktop assets and engine builds; `scripts/` contains validation and packaging tools.
- `docs/wiki/` explains workflows; `docs/requirments/` retains its existing spelling. Generated `target/` and `dist/` are ignored.

## Build, Test, and Development Commands

Install Rust 1.85+, GTK 4.8+ development headers, a C compiler and `pkg-config`; see `README.md` for Linux dependencies. GTK checks require Xvfb.

```sh
cargo build --locked                 # Development build
cargo run --locked -- --demo         # Fixture-only UI
cargo test --locked                  # Unit tests
cargo fmt --all -- --check           # Check Rust formatting
sh scripts/check.sh                 # Tests, build, layouts and GTK smoke checks
sh scripts/check-engines.sh          # Real engines on disposable images
sh scripts/check-ui-recovery.sh      # GTK recovery workflow
sh scripts/check-ui-partitions.sh    # Lost-partition discovery workflow
cargo build --release --locked
sh scripts/package.sh deb            # Also rpm, arch, appdir; outputs dist/
```

Debian control metadata is generated by `scripts/package.sh` and `scripts/package-engines.sh`.

## Coding Style & Naming Conventions

Use Rust 2024, four-space indentation and `rustfmt`. Use `snake_case` for modules/functions, `PascalCase` for types and `SCREAMING_SNAKE_CASE` for constants. GtkBuilder XML uses two-space indentation. Preserve system GTK styling; keep layouts in `ui/` and recovery logic in `src/engine/`.

## Testing Guidelines

Use Rust `#[test]` with descriptive `snake_case` names. Tests live in `src/model.rs` and `src/engine/*tests.rs`; real-engine cases use the `disposable_` prefix and `#[ignore]`. Engine checks require installed tools and separate `/tmp` and `/dev/shm` filesystems. Add regression coverage for behavior or safety changes; no numeric coverage gate is configured. Run relevant GUI checks and record results in `docs/validation.md`.

## Commit & Pull Request Guidelines

Follow history's short imperative subjects, such as `Allow regular image sources to share output storage`. Keep commits focused. PRs should describe behavior, link relevant issues or requirements, list verification and include screenshots for UI changes. Update README/wiki documentation when workflows change.

## Source Safety

Test with disposable images, never real recovery devices. Preserve read-only access, Landlock confinement and destination validation. Device sources require separate physical storage; regular images may share storage but must remain outside output folders.
